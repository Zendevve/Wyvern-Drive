# Phase 1: Shared Protocol SDK

**Goal**: `@disbox/shared` is a browser-and-Node-safe library that chunks files deterministically, hashes content, encodes Merkle trees, and exports types used by every other package.

**Depends on**: Phase 0
**Requirements**: PROTO-01, PROTO-02, PROTO-03, PROTO-04
**Status**: Pending
**Plans**: 1

## Context

The SDK is the foundation for everything else. Web uses it for upload (chunk + hash before sending to server) and download (reassemble + verify). Server uses it for download verification and tree reconstruction. Extension is a thin shim over the web app, so it doesn't directly import the SDK.

**Architectural constraints** (from PROJECT.md + research SUMMARY):
- Pure TS, no React, no Discord, no Node-specific APIs in core.
- WebCrypto for hashing (available in browser and Node 20+).
- Deterministic output across runs and across browsers/Node (test both).
- Dual export: ESM (primary) + CJS (for legacy bundlers).

## Plan 01-01: Chunker, hasher, tree codec, types, tests, esbuild dual export

**Tasks**:

1. **Package config**: update `packages/shared/package.json` to add `esbuild` and `vitest` deps; add `exports` map for both ESM and CJS; add scripts `build`, `test`, `typecheck`.
2. **Types (`src/types.ts`)**:
   - `Chunk { index: number; hash: string; bytes: Uint8Array; size: number }`
   - `ChunkRef { hash: string; size: number; discordMessageId?: string; discordChannelId?: string }` (server side has Discord IDs, client doesn't need them)
   - `FileManifest { id, path, size, mime, chunks: ChunkRef[], createdAt, updatedAt, encrypted?: boolean }`
   - `TreeNode { name, type: 'file'|'directory', hash, size, children? }`
3. **Chunker (`src/chunker.ts`)**:
   - `chunkFile(input: ArrayBuffer | Uint8Array, opts: { chunkSize: number }): Promise<Chunk[]>`
   - Uses WebCrypto subtle for SHA-256.
   - Pure function — same input → same chunks.
   - Handles edge case: input size = 0 (returns single empty chunk), input size < chunkSize (single chunk), exact multiples.
4. **Hasher (`src/hasher.ts`)**:
   - `hashChunk(bytes: Uint8Array): Promise<string>` — 64-char hex SHA-256.
   - `hashTree(nodes: TreeNode[]): Promise<string>` — Merkle-style: leaf hash = `hashChunk(name || hashChildren)`, internal = `hash(sortedChildrenHashes)`.
5. **Tree codec (`src/tree-codec.ts`)**:
   - `encodeTree(root: TreeNode): Uint8Array` — compact binary format: type byte + name length-prefix + hash + (children count + recursive children).
   - `decodeTree(bytes: Uint8Array): TreeNode` — reverse.
   - Round-trip test.
6. **Manifest helpers (`src/manifest.ts`)**:
   - `buildManifest(file: { name, mime }, chunks: Chunk[]): FileManifest`
   - `verifyManifest(manifest, chunks): boolean` — recompute root hash, compare.
7. **Tests (`src/__tests__/`)**: vitest. Cover deterministic chunking, hash stability, tree round-trip, edge cases (empty, single-chunk, multi-chunk), manifest build/verify.
8. **Build (`scripts/bundle.mjs`)**: esbuild produces `dist/index.js` (ESM) and `dist/index.cjs` (CJS) with sourcemaps. `tsc` produces `.d.ts` declarations.
9. **Cross-runtime test**: ensure tests pass in both Node and jsdom (the latter via vitest's `environmentMatchGlobs`).
10. **README**: document the public API with examples; note the zero-dependency constraint for the core; document the dual export.

**Acceptance**:
- `pnpm --filter @disbox/shared test` passes 100% of cases.
- `pnpm --filter @disbox/shared build` produces `dist/index.js`, `dist/index.cjs`, and `dist/index.d.ts`.
- Importing `@disbox/shared` from another workspace package resolves to the ESM build.
- Chunking the same buffer twice produces byte-identical chunks with the same hashes.
- Tree codec round-trips a 1000-file tree losslessly.
