# Phase 9: Mobile PWA

**Goal**: A responsive PWA that works on phones, supports camera capture, touch gestures, and installs to home screen.

**Depends on**: Phase 3
**Requirements**: MOB-01, MOB-02, MOB-03, MOB-04
**Status**: Pending
**Plans**: 2

## Context

v1 explicitly rejected mobile ("Disbox is not currently not supported on mobile devices"). v2 makes mobile a first-class target via a PWA: responsive layout, camera access, touch gestures, home-screen install, offline shell.

**Constraint**: iOS Safari has historically weak PWA support. v1 is best-effort: works on Android Chrome and desktop Safari/Chrome/Firefox/Edge. iOS gets a usable but not perfect experience.

## Plan 09-01: Responsive layout, mobile navigation, touch gestures

**Tasks**:

1. **Responsive layout**:
   - Mobile breakpoint: < 768 px → single-column; sidebar becomes a `<Sheet>` drawer; breadcrumb is shorter.
   - Tablet: 768–1024 px → list + collapsible sidebar.
   - Desktop: > 1024 px → list + persistent sidebar.
2. **Touch gestures**:
   - Swipe-right from the left edge → opens sidebar.
   - Swipe-back in folder navigation → goes to parent folder.
   - Pull-to-refresh on the file list (top of scroll container).
3. **Camera upload**: the native file picker on mobile already includes "Take photo" and "Take video" options. Verify the web app's upload pipeline accepts these without modification. Capture: `<input type="file" accept="image/*" capture="environment">` is the standard pattern; ensure the upload zone uses this on mobile.
4. **Long-press context menu**: replaces right-click on touch devices.
5. **Touch-friendly sizing**: 44 px minimum tap targets; larger padding on lists.
6. **Test on real devices**: Chrome DevTools mobile emulation + physical device smoke test.

## Plan 09-02: PWA manifest, service worker, install flow, offline queue resume

**Tasks**:

1. **`manifest.webmanifest`** at `apps/web/public/manifest.webmanifest`:
   - `name: "Disbox"`, `short_name: "Disbox"`, `start_url: "/"`, `display: "standalone"`, `background_color`, `theme_color: "#5865F2"`, `icons` (192, 512, maskable).
2. **Service worker** (`apps/web/public/sw.js` or generated by `next-pwa`):
   - Cache the app shell (HTML, CSS, JS, icons) for offline.
   - Network-first for API; cache fallback only for navigation requests.
   - Stale-while-revalidate for static assets.
3. **Install prompt**: show a small banner "Install Disbox" with a dismiss button (persisted in localStorage).
4. **Offline queue resume**: the upload queue (from Phase 10) already persists in IndexedDB. Verify it resumes on reconnect when the PWA is launched offline and reconnected.
5. **Update prompt**: when a new SW is available, show a toast "Update available — reload".

**Acceptance**:

- All 4 mobile requirements pass.
- App is usable at 320 px width (Pixel 5 emulator minimum).
- Camera capture works on Android Chrome.
- App installs to home screen on Android Chrome and iOS Safari (Add to Home Screen).
- Offline launch shows the shell; online reconnect resumes queued uploads.
