# Plan 03-03: Upload, Delete, Modals, Toasts, and Detail Panel

Implement the upload flow (drag-and-drop, click-to-upload, queue with progress, concurrency limit), the delete flow with confirmation modal, the toast system, and the file detail panel.

## Traceability

- **Decisions Covered:** D-12, D-13, D-14, D-15, D-16, D-17, D-19, D-20
- **Requirements Covered:** UI-03, UI-04, UI-05

## must_haves

- [ ] `DropZone` wraps the main area; dragging files from the OS shows the accent border + tint
- [ ] `UploadQueuePanel` shows active uploads with filename, progress bar, and cancel button
- [ ] `useUploader` runs uploads with a global concurrency limit of 3
- [ ] Each successful upload immediately calls `POST /api/fs/file/created` so the file shows in the listing
- [ ] Right-click on a file/folder card opens a context menu with Rename (placeholder) and Delete
- [ ] Delete opens a confirm modal; confirming calls `DELETE /api/fs/node` and invalidates the listing query
- [ ] `Modal` and `Toast` components match the UI-SPEC (centered modal, slide-in toasts, 4 s lifetime)
- [ ] Selecting a single file opens a right-side DetailPanel with metadata
- [ ] `apiFetch` 401 responses trigger a redirect to `/` with a "Session expired" toast
- [ ] Unit tests: `lib/concurrency.test.ts` (3-wide concurrency), `hooks/useUploader.test.ts` (mocked fetch)
