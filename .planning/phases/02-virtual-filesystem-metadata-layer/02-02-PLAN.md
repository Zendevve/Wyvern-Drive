# Plan 02-02: Routes, Cascade Delete, and Chunk Recording

Build the `/fs/*` Fastify route layer, record chunk descriptors against file nodes, and implement recursive cascade delete that cleans Discord messages and metadata atomically.

## Traceability

- **Decisions Covered:** D-04, D-05, D-06, D-07, D-09, D-10, D-12
- **Requirements Covered:** FS-01, FS-02, FS-03, FS-04

## must_haves

- [ ] `POST /fs/folder` creates a folder; rejects reserved names and conflicts (409)
- [ ] `GET /fs/list?parent_id=…` returns children for the requester's account
- [ ] `GET /fs/node?id=…` returns the node plus ordered chunks
- [ ] `PATCH /fs/node` renames a node
- [ ] `DELETE /fs/node` performs cascade delete (folder → descendants; file → its chunks via DiscordService + chunk rows)
- [ ] `POST /fs/file/created` records chunk descriptors for a freshly uploaded file (idempotent on `node_id`)
- [ ] All routes gated by `verifyJwt` from Phase 1
- [ ] Integration tests using `app.inject()` with a mocked `DiscordService` for cascade delete

    Create src/services/cascade.ts:
    - Export function `cascadeDelete(db, discordService, webhookUrl, accountId, nodeId): { deletedNodes: number, deletedMessages: string[] }`
    - Wrap in `db.transaction(...)`:
      1. Resolve `getNode` to verify the node exists for this account
      2. Collect descendant ids
      3. Collect chunk message ids
      4. For each batch of 100 message ids, call `discordService.deleteChunk` concurrently with limit 3 — collect failures
      5. If any delete failed, throw so the transaction rolls back
      6. Else call `deleteNodes` and return counts
  </action>
