# Phase 4: Chrome Extension v2

**Goal**: A lightweight MV3 extension that detects Discord message/channel links on the web and offers to open them in the Disbox web app.

**Depends on**: Phase 3
**Requirements**: EXT-01, EXT-02, EXT-03
**Status**: Pending
**Plans**: 1

## Context

Unlike v1 (where the extension was load-bearing for CORS bypass), v2's extension is a **convenience**: the web app works fully without it. The extension detects `discord.com/channels/...` URLs on any page the user visits and offers to deep-link them to the Disbox web app, which can then navigate to that "channel" in the user's stored file tree.

This phase is intentionally small (1 plan). It exists to preserve the v1 extension's value (Discord-link → Disbox) without adding load-bearing complexity.

## Plan 04-01: MV3 manifest, content script, deep-link handler, Chrome Web Store packaging

**Tasks**:

1. **`apps/ext` scaffold** (already stubbed in Phase 0): plain JS, no framework. esbuild for bundling.
2. **`manifest.json`** (MV3):
   - `manifest_version: 3`
   - `name: "Disbox Deep Link"`, `version: "2.0.0"`, `description`
   - `background: { service_worker: "background.js" }`
   - `content_scripts: [{ matches: ["<all_urls>"], js: ["content.js"], run_at: "document_idle" }]`
   - `action: { default_title: "Open in Disbox" }`
   - `permissions: ["activeTab"]`
   - `host_permissions: ["https://discord.com/*", "https://discordapp.com/*"]`
3. **`content.js`**: scans the page for `discord.com/channels/...` anchors; no auto-redirect; just makes the extension icon enabled when a Discord link is present on the page.
4. **`background.js`**: service worker. On extension icon click:
   - Get the active tab URL.
   - If it contains `discord.com/channels/...` or `discordapp.com/channels/...`, extract `(guildId, channelId, messageId?)`.
   - Open the web app at `${WEB_APP_URL}/?ref=ext&guild=${guildId}&channel=${channelId}&msg=${messageId ?? ''}`.
   - The web app handles the `ref=ext` param: if user is logged in, navigate to a "channel view" in the file tree (mapping to be defined in this plan).
5. **Channel → file tree mapping**: simplest mapping is `?channel=<id>` opens a "Channel:<id>" folder in the user's root. Future improvement: store the mapping in server.
6. **Discord.com and discordapp.com**: support both. The redirect script runs on any page; only the icon-click handler is gated.
7. **Build** (`apps/ext/scripts/build.mjs`): esbuild bundles `content.js` and `background.js` to `apps/ext/dist/`. Copies `manifest.json` + icons.
8. **Icons**: 16/48/128 PNGs. Use a simple "D" mark; final branding can be revisited.
9. **Chrome Web Store packaging**: zip the `dist/` folder as `disbox-ext-v2.zip`. Note the CWS publisher account in the README (not part of code).
10. **Dev mode**: load unpacked in `chrome://extensions` with developer mode on; point to `apps/ext/dist/`.

**Acceptance**:

- Extension loads in Chrome with no errors.
- Visiting a page with a `discord.com/channels/...` link enables the extension icon.
- Clicking the icon opens the web app with the channel info in the URL.
- Extension is optional: web app works fully without it.
- Both `discord.com` and `discordapp.com` URLs are detected.
