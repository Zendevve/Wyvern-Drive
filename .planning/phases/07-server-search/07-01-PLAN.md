# Phase 7: Server-Side Search & Metadata Indexing

**Goal**: Fast, server-side search over file metadata (name, path, type, size, mtime) with a query DSL.

**Depends on**: Phase 3
**Requirements**: SRCH-01, SRCH-02, SRCH-03
**Status**: Pending
**Plans**: 2

## Context

Client-side search (substring + fuzzy) is fast for the loaded folder. Server-side search becomes essential as the file count grows beyond what fits in the browser, or when the user wants to search across folders.

**Approach**: SQLite FTS5 virtual table over `nodes` + `files` joined, scoped to the active account.

**Constraint**: server can only search **metadata** (name, path, type, size, mtime, tags). It cannot search file contents (E2EE prevents it). This is documented in the search UI ("Search file names and metadata, not contents").

## Plan 07-01: FTS5 schema, server-side search endpoint, DSL parser

**Tasks**:

1. **FTS5 schema** (Drizzle migration):
   - `file_search` virtual table using `fts5(name, path, mime, tags, content='files', content_rowid='id')`.
   - Triggers to keep FTS in sync with `files` + `nodes` tables.
2. **Search endpoint**: `GET /search?q=<query>&accountId=<id>`.
   - Server parses `q` with a small DSL:
     - Bare word → FTS5 MATCH (with prefix `*` for substring).
     - `ext:png` → `mime LIKE 'image/png'`.
     - `size>10mb` / `size<1gb` → size filter.
     - `mtime:2024` / `mtime:2024-06` / `mtime>2024-01-01` → date filter.
   - Combines FTS5 results with filters via SQL `AND`.
3. **Tests**: unit tests for the DSL parser; integration test for the search endpoint with a populated DB.

## Plan 07-02: Search bar in web app, results UI, filter chip UI

**Tasks**:

1. **Search bar**: in the top nav (or the file list header). Same as Phase 3's filter input but now with server-side fallback when results > 50 (debounced).
2. **Filter chips**: when user types `ext:png`, show a chip "Extension: png" with an X to remove.
3. **Results UI**: list of matching files with breadcrumb path; click to navigate to the file's folder.
4. **Client-side fallback**: while typing, the local folder's contents are filtered client-side. On Enter, server search runs and the result list replaces the folder view.
5. **Empty state**: "No results. Try a different query."
6. **Performance**: server search returns max 100 results; pagination is out of scope for v1.

**Acceptance**:

- All 3 search requirements pass.
- FTS5 search returns results in < 100 ms for a 10k-file dataset (integration test).
- DSL parser handles `ext:`, `size>`, `size<`, `mtime:`, `mtime>`, `mtime<` and bare words.
- Search respects per-account isolation.
