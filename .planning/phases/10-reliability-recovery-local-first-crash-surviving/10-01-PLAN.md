<task type="auto">
  <name>Task 3: Implement Queue Worker and Replay Engine</name>
  <files>web/src/lib/operationQueue.ts</files>
  <read_first>web/src/lib/queueDb.ts, web/src/store/queue.ts, web/src/lib/concurrency.ts</read_first>
  <action>
    Implement `OperationQueue` engine class and worker thread logic:
      - `enqueue(type, payload, idempotencyKey)`:
        - Check for duplicate pending/in-flight tasks using the `idempotency_key`. If exists, return the existing task instead of queueing a duplicate.
        - Generate UUID and insert into `wyvern-drive-queue` DB with status `pending`.
        - Add operation to Zustand store and trigger worker cycle.
      - Worker loop:
        - Respect `isPaused` flag from Zustand store.
        - Pull oldest `pending` operations (FIFO), respect concurrency cap of 2.
        - Transition operation status to `in_flight` and update Zustand + DB.
        - Run the executor function mapping the operation `type` to its API fetch call.
        - If success: transition to `succeeded`, remove/update in DB, and trigger audit event log.
        - If failure:
          - Increment `retries`.
          - If `retries < 5`, transition back to `pending`, apply exponential backoff (1.5s * 1.5^retries) before retrying.
          - If `retries >= 5`, transition to `failed`, store the error message, show toast notification with a link to open diagnostics, and auto-cancel any subsequent queued tasks that depend on the same target ID (e.g. if file upload fails, cancel renaming that file).
      - Replay:
        - On app/worker startup, query IndexedDB for all unfinished operations (both `pending` and `in_flight`).
        - Treat `in_flight` tasks from a crashed session as `pending` and restart/resume them.
  </action>
  <verify>tsc --noEmit passes</verify>
  <done>Core queue worker engine compiles and executes operations in FIFO order with idempotency checks and crash replay</done>
</task>
