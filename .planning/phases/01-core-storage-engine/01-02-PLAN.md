# Plan 01-02: Authentication & Webhook Upload (Chunking)

Implement user authentication via Discord webhooks, stateless HS256 JWT signature and verification, the request pre-handler auth decorator, the Discord service client, and the multipart file upload route `/storage/upload` with concurrency-throttled 24MB chunking.

## must_haves

- [ ] Route `POST /auth/token` validating webhook URL and returning JWT token
- [ ] Pre-handler middleware extracting webhook URL and deriving `accountId` (SHA-256 of URL)
- [ ] Route `POST /storage/upload` accepting multipart file upload, chunking into <= 24MB chunks, and uploading concurrently (concurrency limit = 3) to Discord Webhook
- [ ] Mocked Discord Webhook REST responses in tests to prevent needing live secrets during automated checks

  <action>
    Create src/middleware/auth.ts:
    - Pre-handler hook verifyJwt:
      - Extract token from Authorization: Bearer <token> header
      - Verify using JWT_SECRET
      - Extract webhookUrl from payload
      - Derive accountId by taking crypto.createHash('sha256').update(webhookUrl).digest('hex')
      - Attach request.webhookUrl = webhookUrl and request.accountId = accountId
    Register request decorations in src/app.ts so they are typed and available.
  </action>
  <acceptance_criteria>
    - Pre-handler intercepts requests and rejects with 401 if token is missing, invalid, or expired
